# Безопасность

- Секреты (токен бота, `OPENAI_API_KEY`, пароли БД) только из окружения через `Settings` (`SecretStr`).
  `.env` не коммитится и не читается в ответах; в `.env.example` только пустые значения/заглушки.
- Не логировать секреты и персональные данные; не включать в ответы пользователю трейсбеки.
- В AI уходит только обезличенный контекст (`GenerationRequest`): без Telegram ID, username, chat ID, роли и города.
  Новые поля в запрос добавлять только после проверки, что они не раскрывают личность.
- Весь ввод пользователя (текст, callback data, username, deep-link токены) считать недоверенным: валидировать
  длину и формат, проверять принадлежность заказа тому, кто его меняет.
- Админ-действия проверяют `ADMIN_TELEGRAM_ID` в обработчике, а не только скрывают кнопку.
- SQL только параметризованный; `eval`, `exec`, `pickle.loads`, `yaml.load`, `subprocess(shell=True)` с внешними данными запрещены.
- Не отправлять данные пользователей во внешние сервисы, кроме OpenAI и Telegram.
- Docker: контейнер без root (как в `Dockerfile`), без секретов в образе и в `docker-compose.yml`.
- Зависимости не добавлять и не обновлять без просьбы.
